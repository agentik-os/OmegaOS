01The four questions, answered first

The brief named four concerns. Each one got its own runtime test rather than a reading of the code.

QuestionAnswerEvidence
Shell or ssh injection through session or host names? No. Refuted at two independent layers. 7 payloads inert inside the remote single quotes; ' refused at omega-stream.sh:85; non-slug refused at main.rs:6001
Does the loop ever exit on error? No, the guarantee holds. 3 failure modes, all ended with timeout exit 124 while rendering the error
Unbounded probes that could hang? Mixed. The Rust probes are bounded. The loop's own capture is not. 8.02s on a black-holed box versus 12s producing zero bytes (F-001)
Does $HOME expand remotely, not locally? Yes, remotely, correct. ARGV[6] carries the literal $HOME/.local/bin/rmux, local home absent

The injection question deserves its proof spelled out, because a negative result is easy to assert and hard to earn. A fake ssh placed earlier on PATH printed the exact argv the real loop transmits:

$ PATH=<fake ssh> timeout 4 bash scripts/omega-stream.sh fakehost 'a$(id)' 1 20
[live]  omega stream · fakehost:a$(id) · 17:00:13 · every 1s
ARGV[5]=fakehost
ARGV[6]=$HOME/.local/bin/rmux capture-pane -p -t 'a$(id)' -S -20

That single line answers two of the four questions. $HOME is transmitted literally, so it resolves on the remote box, and the session name arrives inside single quotes. Feeding that exact string to a login shell with a stand-in rmux, which is what sshd does on the far side, shows the payload staying inert:

REMOTE_ARGV[3]=[a$(id)]      # also tested: backticks, ; | && , space, newline
                             # all arrive as ONE literal argument

The only character that could end the quoting is the single quote, and it is refused outright at omega-stream.sh:85. In front of that, the Rust gate at main.rs:6001 refuses every non-slug coordinate before a viewer is ever created. Two layers, each sufficient alone, both unit-tested. shellcheck 0.11.0 is clean on the loop at default severity, which is an independent tool agreeing that the quoting is not accidentally broken.

02Two high findings

F-001high
capture() has no wall clock, so the mirror can freeze forever while the banner still reads live

scripts/omega-stream.sh:131-140 (capture), :177 (the loop), :196-204 (the unreachable staleness path)

ConnectTimeout=10 bounds only the handshake. Once the connection is established, a wedged remote (hung rmux server, half-open TCP, a box that stops answering after the handshake) blocks the loop inside the command substitution forever. Nothing else in the script has a timer.

Reproduction A, never connected. A fake ssh that connects and then sleeps:

$ PATH=<hanging ssh> timeout 12 bash scripts/omega-stream.sh fakehost somesess 1 20
exit=124
bytes of output produced in 12s: 0
frames (banner lines): 0

Twelve seconds at a one second interval, and the operator's screen stays completely blank. No banner, no error, no hint. The "never connected" branch cannot run, because capture never returns.

Reproduction B, the mid-stream freeze, which is the dangerous one. Two good frames, then the source wedges:

$ PATH=<wedges after 2> timeout 14 bash scripts/omega-stream.sh fakehost somesess 1 20
[live]  omega stream · fakehost:somesess · 16:56:48 · every 1s
FRAME 1 from the source box
[live]  omega stream · fakehost:somesess · 16:56:49 · every 1s
FRAME 2 from the source box
   ... nothing for the remaining 12 seconds ...
banner count: 2        frames labelled 'SOURCE GONE': 0
why this is the worst kind of bug for this feature
The staleness machinery exists and is correct: LAST_OK, the age counter, the SOURCE GONE label. It is simply unreachable in this state, because it only runs after capture returns. So the last thing on the operator's screen is a [live] banner with a frozen clock over a stale frame. That is verbatim the state the design forbids in writing, three times over: omega-stream.sh:20-23, stream.rs:23-27, and R-STREAM constraint 2, all of which say a frozen mirror must never be able to pass for a quiet one. This is a promise versus delivery defect, not a missing feature.

The Rust half gets exactly this right, which is what makes the gap visible. probe_host_bounded (stream.rs:414-448) wraps its child in tokio::time::timeout with kill_on_drop(true), and it is measured:

$ omega stream 192.0.2.1:whatever          # black-holed box
Error: cannot list sessions on 192.0.2.1: unreachable over ssh: ... Connection timed out
elapsed=8.02s
$ omega stream list                        # 2 live hosts, probed in parallel
elapsed=0.91s

The short-lived probe is bounded. The long-lived puller, the one whose whole job is to notice a dead source, is not.

Fix shape. Wrap both capture branches in timeout $((INTERVAL + 10)), add ServerAliveInterval=5 and ServerAliveCountMax=2 to the ssh call, and give exit 124 its own rendered state so the existing stale-age banner takes over.
F-002high
viewer_name is not injective, and the CLI then tells you it is streaming the session it is not showing

crates/omega-core/src/stream.rs:241-250 · crates/omega-core/src/session.rs:16,38 · crates/omega-cli/src/main.rs:6063, :6176-6184

The viewer name is the identity of the mirror. It is built by string concatenation and then sanitized, and it collapses two different sources onto one name in two independent ways.

Cause (a), the separator is ambiguous. A local session that happens to look like host-session maps onto the remote coordinate:

local  "matrix-MAC-STREAM" -> stream-matrix-MAC-STREAM
remote "matrix:MAC-STREAM" -> stream-matrix-MAC-STREAM
COLLIDE = true

Cause (b), silent truncation at 48 characters, and this one was reproduced live through the real binary on two real sessions, 43 characters each, differing only in the last character:

$ omega stream -d audit-stream-collision-probe-session-name-A
Streaming ...-A → session stream-audit-stream-collision-probe-session-name

$ omega stream -d audit-stream-collision-probe-session-name-B
Already streaming ...-B in session stream-audit-stream-collision-probe-session-name
  — reusing it (a second puller would interleave).

$ rmux capture-pane -p -t stream-audit-stream-collision-probe-session-nam
[live]  omega stream · local:audit-stream-collision-probe-session-name-A · 16:57
I am SESSION A
I am SESSION A

The operator asked for B, was told they got B, and is looking at A. For a mirror, silently wrong data presented as live is the worst available failure. omega stream list cannot rescue them either, because the "already mirrored" index matches on the same colliding name and marks both sources as mirrored while one viewer exists.

this is not theoretical on this box
A live viewer right now is stream-moonbasecapital-MoonBaseCapital-claude, 44 characters. Four more characters in the session name and it starts truncating. Real OmegaOS worker names sit right at the cliff: two workers named ...-verification-a and ...-verification-b already collide.
Fix shape. Append a short hash of label() whenever the composed name would exceed the cap, make the host and session boundary unambiguous, and at main.rs:6063 verify that an existing viewer is really mirroring the requested target before printing "reusing it".

03Medium findings

F-003medium
No upper bound on --interval, so a typo buys a permanently frozen viewer labelled live

crates/omega-cli/src/main.rs:5990-5995

Only zero is refused. u32::MAX is accepted, the viewer renders exactly one frame, and then sleeps for 136 years under a [live] banner:

$ omega stream -d audit-stream-src --lines 4294967295 --interval 4294967295
Streaming audit-stream-src → session stream-audit-stream-src (... every 4294967295s, 4294967295 lines).
$ rmux capture-pane -p -t stream-audit-stream-src | grep 'omega stream'
[live]  omega stream · local:audit-stream-src · 16:57:45 · every 4294967295s

The --lines half of that command is harmless and the theory was falsified: rmux clamps to the available scrollback, measured at 1522 bytes for a -S -4294967295 request.

Fix shape. Ceilings beside the existing zero checks, in the same style of named error.
F-004medium
The slug rule is enforced in the CLI, not in the module that builds a shell-evaluated command

crates/omega-core/src/stream.rs:220-225 (the doc comment), :274-303 (viewer_command), :475-510 (create_viewer)

The sink is real, not hypothetical. rmux evaluates the new-session command string with a shell:

$ rmux new-session -d -s probe 'echo SHELL_SINK_$(id -un) > /tmp/probe.txt; sleep 3'
$ cat /tmp/probe.txt
SHELL_SINK_vibe

And the unguarded builder will happily produce the payload for a coordinate nobody validated:

viewer_command(Local{ session: "a;id" }) = "/home/vibe/.omega/bin/omega-stream.sh local a;id 3 120"

Not exploitable today: a grep across crates/ finds zero callers outside main.rs, and the CLI gate refuses that coordinate first. It is a latent defense-in-depth gap, one new caller (TUI, daemon, RPC) away from being real, and the compiler will not say a word.

Fix shape. Enforce is_safe_coordinate inside create_viewer and make viewer_command private or fallible.
F-005medium
The two halves disagree about where rmux lives

crates/omega-core/src/stream.rs:254-262 versus scripts/omega-stream.sh:41

Rust prefers $HOME/.local/bin/rmux and falls back to rmux on PATH. The shell hardcodes the canonical path with no fallback. On any box where rmux lives elsewhere (Homebrew on macOS, which the script explicitly supports at :151, or cargo install --root), preflight goes green and the viewer renders a failure forever. Mechanism reproduced by running the loop with a HOME that has no .local/bin/rmux while the session existed:

  state : SESSION NOT FOUND
  exit  : 127
  error : .../nohome/.local/bin/rmux: No such file or directory

Bounded honesty: the full end-to-end divergence is not reproducible on this box, because rmux is at the canonical path here and a viewer inherits the rmux server's HOME. The mechanism is proven, the environment is not available.

Fix shape. Resolve rmux in the script the way rmux_bin() does, and fail loudly when neither location exists.
F-006medium
local is a magic target with no reserved-name guard

crates/omega-core/src/stream.rs:100-103 · scripts/omega-stream.sh:132

Nothing rejects an ssh alias literally named local:

parse_target("local:BluePrint-OS") = Remote { host: "local", session: "BluePrint-OS" }
host_arg() = "local"        <- exactly the loop's local-branch sentinel

Preflight would probe the remote box over ssh and confirm the session there, then the viewer would read a local session of the same name and label it live. No such alias exists in ~/.ssh/config on this box, so it is latent here. It costs one bail! to close.

Fix shape. Refuse local as a host alias, or pass a sentinel that cannot be an alias.

07Method, and what was not done

Fifteen falsifiable tests, most against live artifacts: a real rmux server, the real release binary, the real ssh binary, fake ssh stubs placed earlier on PATH, and a probe crate that depends on the repo crate by path so that every pure-function claim calls the real omega_core::stream functions rather than a re-implementation. Independent tool lenses agreed: release build exit 0, zero clippy warnings attributable to stream.rs, 20 of 20 tests passing in 1.00s, shellcheck clean at default severity. All 43 hinge regions from hinge-analyzer.sh are accounted for: 19 in stream.rs, 23 in main.rs (all inside cmd_stream, stream_attach and cmd_stream_list), and 1 in rules.rs which is doctrine text with no logic.

Every disposable rmux session created for the runtime probes was killed afterwards, and the final session list contains only the operator's own sessions.

Stated limits

  • Phases 21 to 23 (fix execution and re-audit) were not run. The brief is read only, so the fix plan carries every task as pending and no source file was touched.
  • F-005 end to end is not reproducible on this box, because rmux is at the canonical path here. The mechanism is proven, the environment is not available.
  • F-007 escalation to an arbitrary file write was attempted and failed, so it stands as a hygiene gap, not a vulnerability.
  • No hostile payload was fired at a real remote box over real ssh. The far side was reproduced faithfully by feeding the exact transmitted command string to a login shell with a stand-in rmux, which is what sshd does, and it is labelled as a simulation.
  • The 12 second wall clock itself was exercised only by the existing unit test at a 1 second bound. Every live probe was ended earlier by ssh's own ConnectTimeout=8.
  • Out of scope, not pursued: crates/omega-cli/src/main.rs is a 305 KB god file, flagged HIGH by the Phase 0 gather, and this change added roughly 230 lines to it.

08Bottom line

The engineering discipline here is real, and the audit tried hard to prove otherwise. The five constraints are enforced rather than merely documented, the failure taxonomy is typed instead of stringly, preflight refuses to create a viewer that would die instantly, and the injection surface that worried the operator most is genuinely closed at two layers with tests that will keep it closed.

Two things undercut it, and both live in the shell half, which has no automated coverage at all. The loop can freeze forever behind a [live] banner because the one call that must have a wall clock does not have one. The viewer name is not injective, which was reproduced live showing the wrong session under the right label. Fix F-001 and F-002, add the fifteen-line fake-ssh harness that would have caught them, and this is an A.
