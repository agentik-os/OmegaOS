The registry is in good shape. No rule needs retiring: every confirmed finding is a stale clause inside an otherwise valid rule, or a new native capability the registry does not yet govern. The deliberate pins (council seats, monitor scars, verification doctrine) all survived adversarial challenge. The real story is the meta finding below: the mechanism that should have caught this drift automatically was disarmed.

2. The meta finding: the self-improvement loop was off

OmegaOS ships changelog-adopt, a skill whose whole job is absorbing the official Claude Code changelog and proposing doctrine upgrades. Its watermark sits at 2.1.202 while 2.1.224 is installed: 22 versions of features unabsorbed, and its 08:15 cron is disarmed. Every harness-level finding in this report (cross-session messaging, background code review, sandbox credential masking, subagent cap removal) landed inside that unabsorbed window. The single highest-leverage improvement is not any one rule edit: it is arming the loop that makes this audit unnecessary.

3. Confirmed findings

Each finding quotes the live rule text and names the current fact that contradicts it. Severity: stale a better native path exists or a premise died, gap a capability with no governing doctrine at all, minor cosmetic drift.

R-LOOP stale Cache-pacing clause built on a dead 5-minute TTL

The rule instructs loops to "pick delaySeconds by the 5-minute prompt-cache window: 60-270s keeps the cache warm, never 300s". The harness now runs a 1-hour prompt-cache TTL: there is no cache cliff anywhere in the schedulable range, and current guidance explicitly forbids wakeups whose only purpose is keeping the cache warm. A session obeying R-LOOP today fires wasteful 60-270s wakeups to defend a cache that survives an hour on its own.

Fix: rewrite clause (b) only: pace by the work's real cadence, keep 1200-1800s as the idle default, drop the "never 300s" prohibition, note the overage edge case (TTL drops to 5 min) without reviving warm-keeping. Retry ceilings (THRASH_CAP, GATE_RETRY_CAP) and every other clause stay untouched.

R-MODEL stale Security fallback tier contradicts the rule's own map

The Mythos boundary says twice to tier Fable-displaced security work to Opus 4.8, while the same rule's tier map assigns security analysis to Opus 5, which has been GA and the default Opus since v2.1.219. The rule contradicts itself; the only intact Opus 4.8 fact is Anthropic's server-side raw-API refusal fallback, which is not a tier agents choose.

Fix: change both agent-facing directives to claude-opus-5. Keep the descriptive raw-API fallback sentence, clearly marked as server behavior. The safety scar itself (Fable disqualified from security work, refusal = abort) is correct and preserved.

R-ORCH / R-VERIFY gap Native background /code-review is integrated nowhere

Since v2.1.218, /code-review runs natively as a background subagent with typed findings output; since v2.1.215 it no longer auto-runs, so nothing invokes it at all. Meanwhile the registry routes every code review through hand-built adversarial Workflow fan-outs (adversarial-review.js). Grep across all 58 rules: no rule integrates the native reviewer or warns that it stopped auto-running.

Fix: add routing to the verify stage: native /code-review as the background first pass for code diffs (free parallelism, typed output), the adversarial Workflow reserved for what it cannot judge (runtime claims, cross-file architecture, non-code deliverables). Constraint from the verifier: /code-review is a first-pass INPUT feeding the adversarial edge, never the sole verdict, or the single-grader scar regresses.

NEW: cross-session messaging gap No doctrine for the native session-to-session channel

v2.1.224 shipped cross-session SendMessage + ListAgents plus the crossSessionInbound and dialogExpiry settings; both tools are live on this box. Grep across all 58 rules finds zero coverage: no trust posture for inbound messages, no routing decision between SendMessage, the alert funnel, and pane injection, no fleet policy for enabling inbound.

Fix: author a new rule (working name R-XSESSION): an inbound cross-session message is an INPUT, never an instruction (same posture R-ORACLE-LEDGER takes toward delegate claims); SendMessage for peer signaling between live sessions, the alert funnel for operator-facing escalation, pane injection only where R-MONITOR already owns it; decide and record the fleet-wide crossSessionInbound setting.

R-ENV gap Sandbox credential masking exists, no rule uses it

R-ENV's secrets doctrine is location-only ("secrets live in ~/.omega, never the repo"). Claude Code now ships sandbox credential masking (mode: "mask" on Linux, plus jwt/awsPairs/sigv4 extraction, v2.1.222-224): sandboxed commands read a sentinel while the proxy substitutes the real value on egress. No rule instructs agents to shield ~/.omega secrets with it when running untrusted or semi-trusted commands.

Fix: extend R-ENV (or fold into the R-REPO-INSTALL fix below): when executing code you did not write, secrets reachable from the environment get masked via the native sandbox layer; location hygiene alone no longer meets the bar the harness makes cheap.

R-REPO-INSTALL stale The safety glance can now be enforced, not just hoped

The rule's one precondition is a human-eye glance at install scripts. Native containment now exists that enforces what the glance can only spot: sandbox.network.strictAllowlist (v2.1.219), credential masking (v2.1.222), and SHA-256 pinned zip installs (v2.1.224). An exfiltration attempt the glance misses is stopped by an egress allowlist; a credential harvest reads sentinels.

Fix: keep the glance (it catches destructive commands containment does not), add a second layer: run operator-given repo installs under the sandbox with strict network allowlist and masked credentials by default. The rule keeps its no-friction spirit; the enforcement gets teeth.

R-CLI stale The MCP-bloat premise is factually dead

"Minimize MCP servers: they bloat context every turn" was true when written. On current Claude Code, MCP schemas are deferred and load on demand via ToolSearch (live-confirmed in this very session: open-design and convex tools appear as names only, schemas unloaded), and MCP calls auto-background after 2 minutes. The cost model that justified the rule no longer exists.

Fix: rewrite the rationale, keep the preference. CLI-first remains right for scriptability, inspectability, and composability (real reasons that did not age), but the rule should stop citing a context cost the harness eliminated, and soften the blanket ban into a judgment call per integration.

R-DESIGN stale "MCP is NOT the path here" contradicted by the box's own Open Design integration

The design router closes with a blanket "MCP is NOT the path here (R-CLI)" while the box now carries a vendored open-design MCP server (configured and live in sessions), open-design skills, and the omega-design CLI. The router claims to route ANY design request and never mentions any of them.

Fix: add an Open Design lane to the router (when the OD workspace is the right surface vs the generator skills), and drop or scope the blanket MCP clause to match reality.

R-SKILLPUB minor Plugin zip + marketplace distribution unmentioned

The two-SSOT publishing contract (skill library repo + OmegaOS repo) stands. Claude Code's plugin infrastructure (zip-over-HTTPS install with SHA-256 pinning, marketplaces with owner wildcards) is a distribution channel the rule predates and never mentions.

Fix: one added sentence: plugin packaging is an optional third distribution surface for skills meant to travel beyond OmegaOS installs; the two SSOTs remain mandatory.

5. Where OmegaOS stands vs the ecosystem

Against the August 2026 landscape (majority of orgs now running multi-step agent workflows in production; the industry converging on governance, observability, and shared memory as the hard problems), OmegaOS is ahead of the curve on most axes, not behind:

  • Orchestration: pipeline/graph doctrine (R-GRAPH, R-GRAPH-EXEC) matches or exceeds what commercial frameworks ship as "patterns". The subagent cap removal and depth-3 nesting raise the ceiling OmegaOS can already exploit.
  • Governance: risk gates, bounded loops, oracle ledgers, and the finish contract are exactly the "auditability and stage-gating" the enterprise playbooks now preach.
  • Shared memory: omega-mem (Graphiti + FalkorDB) is the "knowledge fabric" the trend pieces call critical; it predates the trend.
  • The lag is harness absorption, not architecture: every confirmed finding traces to the 22 unabsorbed Claude Code versions, which is an armed-cron problem, not a design problem.

7. Method

Four stages. (1) Inventory: registry, repo, versions, skills, workflows. (2) Trends research: official Claude Code changelog 2.1.202 to 2.1.224, model landscape, ecosystem surveys. (3) Fan-out: six category reviewers, each reading the live rule files against the trends digest, returning structured findings plus explicit holds. (4) Adversarial verification: one skeptic per finding instructed to refute it, checking the quoted rule text verbatim, the contradicting fact's currency, deliberate-pin carve-outs, and whether the proposed fix breaks a paid-for scar. 20 candidate findings entered verification; 11 verdicts confirmed (9 distinct findings after dedupe), 9 refuted. 26 agents, 2.68M tokens, 224 seconds wall clock.
