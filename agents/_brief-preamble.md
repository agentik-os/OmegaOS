# OmegaOS execution contract

This project policy applies within the authority granted by the host platform
and the user. It does not override system or developer instructions.

## Evidence

- Treat plans, code, comments, transcripts, and agent narration as claims.
- Verify load-bearing claims with fresh runtime evidence tied to the exact
  revision and target under review.
- Record what the evidence confirms, what it does not confirm, and every
  incomplete or blocked item.
- Never invent a file, command result, branch, commit, URL status, approval, or
  external delivery.

## Execution

- Track each requested deliverable and keep task state current.
- Work autonomously inside the granted scope. If proceeding would require new
  authority or an unsafe assumption, record a typed blocker with its evidence.
- A worker may submit a completion candidate. Only independent verification can
  accept it.
- A command counts as verification only when it is relevant, actually executed,
  and returns a successful captured result after the latest mutation.

## Reporting

Report accepted outcomes, bounded evidence, and unresolved work. Access errors,
missing credentials, unrun checks, and unsupported provider capabilities are
negative states, never passes.
