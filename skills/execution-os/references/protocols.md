## 1. Bootstrap

Run a conversational setup in no more than two passes.

### Pass A: reality

Collect current roles, obligations, deadlines, available focused hours, energy pattern, active projects, unfinished commitments, and recurring failure patterns.

### Pass B: choice

Choose the season's `WIN` domain, define maintenance floors, select one primary outcome, name exclusions, and schedule the first proof checkpoint.

Deliver:

- execution profile;
- season card;
- outcome contract;
- active WIP;
- weekly cadence;
- first daily command.

## 2. Cycle planning

Default to a 6-12 week cycle.

1. Write the target state in past tense and make it observable.
2. Record baseline and gap.
3. Identify the constraint that most limits progress.
4. Generate at most three strategic bets.
5. Choose one bet with an early falsification signal.
6. Create 3-5 evidence milestones.
7. Budget capacity at 70%, including maintenance domains.
8. Write the kill list.
9. Define a stop/pivot threshold.
10. Ship the first proof within 72 hours when possible.

## 3. Weekly war room

Timebox to 25 minutes.

### Close the prior week

- List only shipped or verified evidence.
- Calculate outcome delta and reliability.
- Identify one bottleneck and one avoided decision.
- Close, defer, delegate, or cancel every open commitment.

### Design the new week

- State one weekly win.
- Choose up to three deliverables.
- Attach acceptance and proof to each.
- Estimate focused minutes and calendar windows.
- Reserve 30% uncertainty capacity.
- Name the likely failure and pre-commitment.
- Put everything else on `NOT THIS WEEK`.

### Weekly output

`Weekly win -> Deliverables -> Blocks -> Risks -> Kill list -> Proof review time`

## 4. Daily command

Timebox planning to 8 minutes.

### Morning

1. Rate usable capacity: `RED`, `AMBER`, or `GREEN`.
2. Check immovable events and dependencies.
3. Select one must-win proof.
4. Select at most two supporting commitments.
5. Place the hardest high-value block at the best energy window.
6. Define phone, tab, notification, and messaging rules.
7. Name the first physical move.

### Capacity classes

- `GREEN`: normal deep work; up to three commitments.
- `AMBER`: constrained; one must-win plus one maintenance item.
- `RED`: protect health/obligations; one minimum viable proof or explicit recovery.

### Shutdown

Timebox to 7 minutes.

- Capture evidence.
- Classify each commitment.
- Park open loops.
- Record energy and friction.
- Set tomorrow's first move.
- End work intentionally.

## 5. Focus block

### Start ritual, under two minutes

1. Restate the one deliverable.
2. Open only required materials.
3. Remove or silence distractions.
4. Choose a block: 15, 25, 50, or 90 minutes.
5. Start with a deliberately imperfect first action.

### During

Use a distraction capture line. Do not switch contexts. If blocked for more than five minutes, classify the blocker and choose: solve, shrink, ask, substitute, or stop.

### End

Record focused minutes, output, evidence, next action, and whether acceptance passed. Take recovery proportional to cognitive load.

Before switching projects or stopping mid-commitment, generate a Context Capsule. Require a last output and one physical resume action so re-entry does not depend on memory.

## 6. Interruption and capture

Use `CAPTURE -> CLASSIFY -> RETURN`.

- Capture the incoming thought in one line.
- Classify it as urgent, schedule, delegate, reference, or discard.
- Return to the last explicit next action.

Only switch immediately when delay creates material harm or blocks a person with a higher-value dependency.

## 7. Rescue protocols

### Overwhelm reset, 10 minutes

1. Stop adding tasks.
2. Brain-dump open loops.
3. Mark actual deadlines and consequences.
4. Choose one stabilization action.
5. Cancel, defer, or communicate the rest.
6. Start a 15-minute ignition block.

### Procrastination

Diagnose before prescribing. Then use one:

- shrink to a five-minute visible action;
- produce an ugly zero draft;
- create a social or external checkpoint;
- remove a start-up friction;
- obtain the missing decision;
- stop the outcome if commitment is false.

### Late commitment

1. Tell the truth about current status.
2. Protect or renegotiate the external promise early.
3. Reduce to the smallest acceptable scope.
4. Ship a partial proof when useful.
5. Record why prediction failed.
6. Change future estimates or gates.

For a promise to another person, use the Promise Ledger. A due date without a `notice_by` date is incomplete. When the notice threshold is reached, choose deliver, shrink, renegotiate, or cancel explicitly; never defer the internal commitment while leaving the stakeholder expectation invisible.

### Seven-day restart

- Day 1: reality audit and open-loop cleanup.
- Day 2: environment and calendar repair.
- Day 3: first small proof.
- Day 4: protected deep-work block.
- Day 5: ship something externally.
- Day 6: recover and consolidate.
- Day 7: evidence review and next-week contract.

Never rebuild the entire life system during a restart.

## 8. Reviews

### Daily review

Ask:

- What proof exists?
- What was merely touched?
- What moved the primary outcome?
- What stole attention?
- What did energy enable or prevent?
- What is tomorrow's first move?

### Weekly review

Add:

- outcome delta;
- reliability;
- focused minutes and conversion;
- oldest WIP;
- quality/rework;
- avoided decision;
- continue, stop, start;
- one system experiment.

### Monthly or cycle review

Add:

- target versus actual;
- bet validity;
- constraint change;
- portfolio balance;
- recovery debt;
- capabilities gained;
- decisions to preserve;
- next cycle: recommit, pivot, pause, or close.

## 9. Travel and low-capacity modes

### Travel mode

Protect only one portable outcome, essential maintenance, capture, and recovery. Avoid starting complex new work. Use 25-minute blocks and asynchronous commitments.

### Low-energy mode

Separate physical depletion from emotional resistance. For physical depletion, reduce cognitive load and protect recovery. For resistance, shrink the start and obtain a fast proof. Never compensate with chronic sleep loss.

### Crisis mode

Prioritize safety, health, legal/financial deadlines, and communication. Suspend growth goals temporarily. Resume with a reality audit rather than a backlog marathon.

## 10. Canonical T0-T4 scheduler

### T0 Capture — on interruption, 20 seconds

Write the item in one inbox, tag it `O` outcome, `C` commitment, `A` action, or `?` undecided, then return immediately. Process it only at T2.

### T1 Boot — every morning, five minutes

Read the One Page, name today's Single Thread, confirm the first physical action written last night, defend the focus block, and start before opening communication channels when obligations allow.

### T2 Halt — every evening, five to seven minutes

Drain the capture inbox to zero, close what closed, log one immutable reality signal, write tomorrow's first action, and stop deliberately.

### T3 Reset — weekly, 25 minutes

Count open commitments, kill or renegotiate stale loops, rewrite the next action for every survivor, read seven signals, set one weekly truth, and book the blocks.

### T4 Audit — monthly, 45 minutes

Score outcome movement, run the drift test, kill at least one obsolete item, start at most one new outcome within the three-outcome ceiling, and repair the most frequently skipped scheduler cycle.

### Installation sequence

- Hour zero: dump all loops, choose up to three outcomes, reduce open commitments to seven, fill the One Page, and write tomorrow's first action.
- Week 1: install T2 only.
- Week 2: add T1.
- Week 3: add T3.
- Week 4: add T0.
- Day 30: run the first T4.

When a cycle is missed, resume at the next T2 without catch-up or punishment.
