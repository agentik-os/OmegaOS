# 00-CAIO-Engagement-Plan.md + Phase Tracker — templates

caio-master writes exactly two files, into its own dedicated `./caio-engagement/` dir (never a phase
owner's output dir). Both are *living* — re-run the Workflow to refresh them as gates close. Numbers are
**consumed** from the owner artifacts (`./caio-readiness/`, `./business-os/`, `./company-ai-os/`,
`./caio-run/`), never invented (Iron Law 5 / L1).


### Status vocabulary (one column, four values + the P0 halt)
- **✅ SUFFICIENT-VERIFIED** — artifact present + passes the owner's discipline checks + ≥2-of-3 ratified.
- **🟡 IN-PROGRESS** — artifact exists but partial / fails an owner check.
- **⚪ READY** — predecessor verified; this phase's artifact is absent — route to the owner now.
- **🔒 BLOCKED-UPSTREAM** — a predecessor gate is still open; this phase cannot start.
- **⛔ HALTED** — P0 only: a NOT-YET/REDIRECT verdict; the engagement is not sold and does not proceed.

### Rules for the tracker
- **Evidence column is mandatory** for any ✅ or 🟡 — a cited file:path or quote (R-CITE). An uncited row
  is a surface claim, refused.
- **Verified column** carries the skeptic vote (`2-of-3` / `1-of-3` / `not-yet`) for any ✅.
- **Route column** names the exact OWNER command for any non-✅ phase — never "caio-master will build it".
- **P0** is ✅ only on a GO; a NOT-YET/REDIRECT is ⛔ HALTED, and the Route column carries the path back.
- The tracker is regenerated every run; it is the single source of truth for "where are we in the
  engagement".
