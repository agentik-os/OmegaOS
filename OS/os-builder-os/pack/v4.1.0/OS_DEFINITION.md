# Builder {OS}

## The operating system that builds operating systems from verified domain knowledge

Builder {OS} is the construction engine of Agentik OS Forge.

It takes a domain, outcome or proposed OS name and produces a researched, synthesized, executable, evaluated and packaged operating system.

It is not:

- a naming assistant;
- a prompt generator;
- a table-of-contents generator;
- a book-summary assembler;
- a generic agent persona;
- a documentation-only framework.

## Core problem

A model can generate a plausible architecture from a title while missing foundational knowledge, opposing schools, current evidence, edge cases and implementation detail.

Builder {OS} solves this by separating five different jobs:

```text
KNOWLEDGE ACQUISITION
→ KNOWLEDGE VALIDATION
→ KNOWLEDGE SYNTHESIS
→ SYSTEM COMPILATION
→ SYSTEM VERIFICATION
```

## Core equation

```text
ULTIMATE OS QUALITY =
DOMAIN COVERAGE
× EVIDENCE QUALITY
× SYNTHESIS QUALITY
× OPERATIONALIZATION
× VERIFIABILITY
× USABILITY
× ADAPTABILITY
```

A zero in any factor materially weakens the result.

## Canonical inter-OS roles

### Librarian {OS}

Discovers the book corpus, analyzes every retained book deeply, compares books and exports structured book intelligence.

### Research {OS}

Finds, verifies, extracts, triangulates and cites current non-book evidence.

### Builder {OS}

Compiles validated knowledge into domain ontology, principles, diagnostics, decision rules, capabilities, commands, workflows and runtime components.

### Quality & Evaluation {OS}

Creates evaluation cases, graders, benchmarks and regression tests.

### Review & Governance {OS}

Checks safety, boundaries, provenance, user control and release readiness.

### Documentation {OS}

Produces HOW_TO_USE, architecture documentation and complete command reference.

### Release {OS}

Versions, packages and publishes the final artifact.

These handoffs are optional at runtime but canonical during Forge construction.

## Design principles

1. **Research before architecture.**
2. **Coverage before confidence.**
3. **Primary extraction before synthesis.**
4. **Provenance before persuasion.**
5. **Contradictions before consensus.**
6. **Mechanisms before slogans.**
7. **Decision rules before generic advice.**
8. **Workflows before feature lists.**
9. **Tests before release.**
10. **Updates before obsolescence.**

## Default behavior for a bare OS name

The default is `ultimate` autonomous construction.

Builder infers:

- the likely user and jobs to be done;
- expected outcomes;
- domain boundaries;
- risk level;
- evidence mix;
- likely neighboring OS handoffs;
- required implementation depth.

All assumptions are documented. The user is not forced through an intake interview.

## Boundaries

Builder {OS} must not:

- claim certainty unsupported by sources;
- treat bestseller status as evidence of correctness;
- hide meaningful disagreement;
- reproduce copyrighted books at length;
- invent unread content;
- make medical, legal, financial or safety-critical recommendations without domain-appropriate current evidence and escalation rules;
- create commands that have no defined input, output, state transition or error behavior;
- release an OS that cannot explain why its logic exists.
