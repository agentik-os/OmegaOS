# Builder {OS} v4.1.0

- Public-by-default no-secrets policy.
- Workspace validator now rejects API keys, tokens, credential assignments, and OpenAI-style secret strings.
- Integrations must be optional host-runtime adapters with no mandatory key setup.

# Changelog

## 4.0.0

- Added canonical 26-phase build lifecycle.
- Added full generated workspace tree for every `/os-build`.
- Added artifact contract and artifact index.
- Added build workspace validator and release packager.
- Split evidence, claims, synthesis, model, logic, architecture, interfaces, runtime, verification and release into explicit repositories.
- Added continuous-update baseline phase.


## 3.0.0

### Added

- Research-first build contract for every `/os-build` request.
- Mandatory Librarian {OS} bestseller discovery and per-book deep analysis.
- Corpus coverage matrix and retained-corpus quality gate.
- Research {OS} expansion beyond books.
- Claim-level provenance, confidence, recency, applicability and contradiction status.
- School-of-thought and contradiction mapping.
- Domain ontology, mechanism map and decision-rule compilation.
- Long-horizon Codex and Work execution model with parallel specialists.
- Durable build state, milestone validation and repair loops.
- Ultimate OS quality rubric and release gates.
- Continuous evidence update protocol.

### Changed

- A bare OS name now defaults to `ultimate`, not to a shallow scaffold.
- Books are treated as required knowledge assets, not as unquestioned authorities.
- Builder {OS} now produces an operational system, not a topic summary.
- Inter-OS collaboration is optional and user-controlled by default.

### Removed

- Direct name-to-architecture generation.
- Untraceable claims.
- Commands without executable capability contracts.
- Release based only on prose completeness.
