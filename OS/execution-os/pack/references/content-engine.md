## 1. Editorial doctrine

Teach from the mechanisms, artifacts, experiments, and evidence of Execution OS. Do not paraphrase a competitor slide by slide. Use widely known concepts only with original framing, verified sources where needed, and Gareth's applied examples.

Content promise:

> Stop consuming productivity advice. Install a personal execution system that produces visible proof.

## 2. Benchmark lessons

The audited public benchmark uses nine tightly related carousels around mental models, cognitive bias, human behavior, discipline, calm, strategic thinking, and decision making. Its repeated pattern is:

`Authority-led hook -> numbered ideas -> simple explanation -> micro-advice -> save/share -> comment keyword for product`

Retain the clarity, cadence, numbered progression, and single CTA. Improve originality, evidence, narrative, application, and product continuity. Avoid repetitive captions, borrowed authority as the main hook, and generic lists disconnected from the product.

## 4. Carousel grammar

Default 8-slide structure:

1. Contrarian outcome hook.
2. The costly problem.
3. Mechanism or model.
4. Diagnostic example.
5. Protocol.
6. Applied Gareth case or template.
7. One immediate action.
8. CTA linked to the Execution OS.

Alternate grammars:

- Before/after operating system.
- One failure, three diagnoses, one fix.
- Myth versus mechanism.
- Scorecard or audit.
- 24-hour experiment.
- Decision tree.

## 5. Nine original flagship carousels

Create these as superior counterparts to the nine benchmark themes:

1. **You do not need more motivation. You need a finish line.** Teach outcome, definition of done, evidence, and the two-minute start.
2. **Five biases that secretly destroy execution.** Planning fallacy, sunk cost, present bias, optimism bias, and completion bias, each with an Execution OS countermeasure.
3. **Why smart people still fail to execute.** Ambiguity, excess WIP, delayed feedback, emotional avoidance, and false commitment.
4. **The Decision Stack for high-stakes weeks.** Reversibility, expected value, opportunity cost, second-order effects, and stop rules applied to one decision.
5. **Discipline is an environment, not a personality.** Friction audit, defaults, pre-commitment, visible cues, and recovery.
6. **Think clearly when everything feels urgent.** Consequence, deadline, leverage, dependency, and deletion filter.
7. **The five forces controlling your behavior today.** Identity, environment, energy, social expectation, and feedback latency.
8. **The anti-overthinking protocol.** Facts, assumptions, decision deadline, smallest test, irreversible boundary.
9. **Become evidence-driven, not busy.** The five completion classes and a seven-day proof audit.

Each carousel must include an original example and one downloadable/useful artifact from Execution OS.

## 6. Ninety-day publishing plan

### Phase 1 — Problem ownership, days 1-30

- Publish 4 carousels per week.
- Establish the enemies: fake productivity, endless planning, motivation addiction, and task-count vanity.
- Release the nine flagship carousels across the first three weeks.
- Use the fourth week for personal audits and audience questions.

### Phase 2 — Method ownership, days 31-60

- Teach the Daily Command, Weekly War Room, Proof Ledger, WIP Gate, Focus Block, Miss Protocol, and Seven-Day Restart.
- Publish one real weekly scorecard with sensitive details removed.
- Turn high-save carousels into short videos and newsletter essays.

### Phase 3 — Category ownership, days 61-90

- Publish case studies and transformations.
- Compare Execution OS with planners, habit trackers, and motivational content.
- Show how Mindset OS, Habit Tracker OS, and Execution OS exchange state without collapsing into one system.
- Launch a 7-day Execution Reset challenge.

### Weekly cadence

- Monday: diagnosis carousel.
- Wednesday: framework carousel.
- Friday: applied protocol/template.
- Sunday: proof, review, or founder experiment.

## 7. Production and measurement

### Batch pipeline

1. Capture one real execution problem.
2. Attach the relevant OS mechanism.
3. Research and verify any factual claim.
4. Draft the hook and one-sentence transformation.
5. Build the 8-slide argument.
6. Run originality, clarity, and application checks.
7. Design from a reusable visual system.
8. Publish with one CTA.
9. Log saves, shares, qualified comments, DMs, and conversions.
10. Turn audience objections into the next carousel.

### Quality gate

Reject a draft when:

- it could belong to any productivity account;
- it contains only a list and no mechanism;
- it uses authority without application;
- it offers more than one CTA;
- it has no original example, diagnostic, protocol, or artifact;
- it makes a factual claim without a source plan;
- it repeats a prior post without a new insight.

### Funnel

Use one keyword per campaign, but deliver a useful first win rather than a generic lead magnet. Recommended path:

`Carousel -> 3-minute Execution Audit -> personalized result -> 7-day reset -> full Execution OS`

Measure qualified audit completions and verified seven-day outcomes, not only comments.
